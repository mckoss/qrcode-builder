# QR Code Builder

An offline-first Progressive Web App for making QR codes. No accounts, no ads, no cookies. Everything you make runs and is stored on your device; the only thing sent anywhere is an anonymous, cookieless page-view count (page address, referrer, screen size, language, browser and approximate country) to a self-hosted [Umami](https://umami.is) at stats.mckoss.com. Your QR content, library and scans are never sent.

**Live:** https://mckoss.github.io/qrcode-builder/ (once GitHub Pages is enabled; see [Deploying](#deploying))

## Features

- **Code types:** Wi-Fi (WPA/WPA2/WPA3 by default, WEP, open, hidden networks), plain text, URL, email, phone, SMS, contact (vCard 3.0), geo location, and calendar event.
- **Error correction:** L (7%), M (15%), Q (25%), or H (30%).
- **Transparent backgrounds** so a code can sit on top of another image, or a solid background color.
- **Code color:** any color for the dark ("positive") modules, with warnings for low-contrast or inverted combinations.
- **Adjustable quiet zone:** 0–8 modules.
- **Optional text:** a description above the code, and the decoded content below it (for example the network name and password, for people who can't scan).
- **Export:**
  - PNG at any width.
  - PDF with the page cropped to the content and vector modules, at a physical size in inches or cm.
  - SVG.
  - Copy to clipboard, or share via the system share sheet where supported.
- **Clone by scanning:**
  - Read an existing QR code with the camera, or from an image file or a pasted image.
  - Zoom in to pick out one code: pinch, slider, +/− or mouse wheel. The camera's own (often optical) zoom is used first where the browser supports it, then up to 4× digital zoom. Only the code inside the viewfinder square is read, nearest the center if several are visible.
  - The content is recognized as Wi-Fi, URL, email, phone, SMS, contact (vCard or MECARD), location or event, then added to the library as an editable code. Anything else becomes text.
  - If the original has details the form can't represent (for example a second phone number or a recurrence rule), you're told what would be left out, and you can keep the exact original text instead.
  - Uses the browser's `BarcodeDetector` where available, otherwise [jsQR](https://github.com/cozmo/jsQR). Both work offline.
- **Library:**
  - Codes are saved when you save, download, copy, share or scan them.
  - Only source data is stored: each code's type, non-empty fields, style and text options. No images and no encoded payload are kept, since everything is regenerated and redrawn on demand.
  - A typical code is a few hundred bytes. The app is designed for libraries of hundreds of codes, and the browser's roughly 5 MB per-site `localStorage` holds far more. There's no count limit, and nothing is ever deleted automatically: if storage does fill up, the save fails with a message.
  - Every stored code can be revised: open it and your changes save back to the same code. "Save as copy" branches it, "New code" starts fresh, and you're warned before unsaved changes are discarded.
  - Browse, search, pin, delete with undo, and clear.
  - **Export** saves the whole library as one JSON file. **Import** merges such a file without creating duplicates:
    - Codes already in the library, or repeated within the file, are skipped.
    - If the file has a newer revision of a code you already have (the same code edited on another device), it replaces the older one.
    - A pin on either side is kept.
    - Exports from earlier versions can be imported.
- **Offline:** a service worker precaches the whole app after the first visit, and it can be installed as an app.

## Development

```bash
npm install
npm run dev        # local dev server
npm test           # unit tests (vitest)
npm run e2e        # end-to-end browser tests (Playwright)
npm run typecheck  # type-check the app and the e2e tests
npm run build      # type-check + production build into dist/
npm run preview    # serve the production build
```

The PWA service worker is only generated by `npm run build`. Use `npm run preview` to test offline behavior.

### Tests

- **Unit tests** (`src/*.test.ts`, vitest) cover:
  - payload encoders and the scan parsers (round trips for every type, plus codes from other generators);
  - layout and SVG output;
  - library storage, migration and import.
- **End-to-end tests** (`e2e/*.e2e.ts`, Playwright + Chromium) run against a production build served under `/qrcode-builder/`, as on GitHub Pages. They cover:
  - exported PNGs decoding back to the exact payload, with transparency, colors, PDF page size and fonts, and SVG output;
  - every content type and the phone layout;
  - camera scanning (with a simulated camera) and image scanning;
  - revising library codes;
  - library export/import, search, pin, undo and migration;
  - installability and full offline use (reload, PDF export, image scan and Library with the network off).
- The e2e tests generate their own QR images at run time, so there are no binary fixtures.
- First run: `npx playwright install chromium` downloads the browser.
- CI runs both suites on every push and pull request, and the GitHub Pages deploy waits for them. If the e2e job fails, the Playwright report and traces are uploaded as an artifact.

### Layout

| Path | Purpose |
| --- | --- |
| `src/qrtypes.ts` | Per-type form fields, payload encoders (`WIFI:`, `mailto:`, vCard, VEVENT, …) and decoded-text renditions |
| `src/parse.ts` | Payload parsers (the inverse of the encoders) used when cloning a scanned code |
| `src/scan.ts` | Camera and image QR reading |
| `src/qr.ts` | QR matrix generation (via [`qrcode`](https://github.com/soldair/node-qrcode)) |
| `src/render.ts` | Shared layout plus the canvas (preview/PNG) and SVG renderers |
| `src/pdf.ts` | PDF export via [jsPDF](https://github.com/parallax/jsPDF), lazy-loaded |
| `src/store.ts` | Draft and history persistence |
| `src/main.ts` | UI wiring |
| `scripts/gen-icons.mjs` | Regenerates `public/favicon.svg` and the PNG app icons (needs Playwright) |

### Notes

- PDF text uses the built-in Helvetica and Courier fonts when it is Latin-1. Other scripts (CJK, emoji, …) are drawn as a high-resolution image in the PDF, so they still render correctly.
- Calendar event times are converted from your local time zone to UTC.

## Versioning

The app follows [Semantic Versioning](https://semver.org/). `package.json` is the single source of truth: its `version` is injected at build time and shown in the header. For each release:

1. Bump the version: patch for fixes, minor for new backward-compatible features, major for breaking changes. A breaking change includes anything that makes existing saved library data or exports unreadable.
2. Add an entry to [CHANGELOG.md](CHANGELOG.md).

## Deploying

`.github/workflows/deploy.yml` tests and builds every push and pull request, and deploys `main` to GitHub Pages. To turn it on, go to **Settings → Pages** and set **Source** to **GitHub Actions**.

To host under a different path, set `BASE_PATH` (for example `/` for a custom domain) when running `npm run build`.
